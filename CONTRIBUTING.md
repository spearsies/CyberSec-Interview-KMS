# Contributing to CyberSec-Interview-KMS

First off, thank you for considering contributing to this Knowledge Management System! It is community contributions that make this a robust resource for everyone.

## 🌟 How Can I Contribute?

### 1. Adding New Interview Questions
If you've recently gone through an interview or found a great resource, add it to `30 - Interviews`.

Please use the existing template in `99 - Meta/Templates` and follow the canonical frontmatter in `99 - Meta/_Metadata Standard & Quiz Setup.md`.

Ensure you tag the domain (e.g., `appsec`, `analyst`, `cloud`) so others can find it.

### 2. Expanding Technical Deep Dives
Help us bridge the gap between "knowing the answer" and "understanding the technology." Add or improve atomic concept notes in `20 - Key Concepts`.

### 3. Refactoring & Linking
If you see a question that should be linked to a technical concept but isn't, feel free to wire up the internal wiki-links between notes.

## 🚀 The Contribution Workflow

- **Fork the Repository:** Create your own copy of the project.
- **Create a Branch:** `git checkout -b feature/AmazingContribution`.
- **Commit Your Changes:** `git commit -m 'Add: New scenario for Ransomware IR'`.
- **Push to the Branch:** `git push origin feature/AmazingContribution`.
- **Open a Pull Request:** Describe what you added and why it's valuable.

## 📝 Style Guidelines

- **Markdown only:** Since this is an Obsidian vault, keep everything in clean Markdown.
- **Relational:** Try to include at least two internal links in every new note.
- **Tone:** Keep explanations professional, technical, and objective.

## ⚖️ Code of Conduct

By contributing, you agree to keep discussions respectful and focused on helping the community grow. Any offensive or low-effort content will be rejected.

Happy contributing!
